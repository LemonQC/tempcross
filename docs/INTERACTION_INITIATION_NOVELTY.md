# 交互启动机制：创新性边界与项目判断

基准：`b84bb7e9ad12f582e87d74bc267ef50da14e3c08`；检索及方法核对日期：2026-11-10。仅讨论本轮交互启动问题，不重启此前算法方向。

**结论：存在值得准确记录的行为失配，但尚未识别区别于已有方法、可以支撑新算法的决策机制。本轮不设计或开发网络。** 以下是原论文方法范围与本数据的对应分析，不是本仓库完成了这些方法的训练、复现或公平对比。

## 已有方法覆盖什么

| 方法及原始来源 | 方法实际覆盖 | 对本题的边界 |
| --- | --- | --- |
| [Cloak v2，2026-09-25](https://arxiv.org/html/2606.22836v2)，§4.1–4.4；[作者项目](https://tml.stanford.edu/cloak/) | 根据机器人几何、本体状态及相机参数构造掩码；训练时增强掩码并屏蔽相关视觉注意力；部署时用目标具身掩码，并通过指尖位姿重定向状态/动作。其主要遮挡视角为腕相机 | “去掉具身外观以增强视觉不变性”已存在。当前BARX仅外部RGB、没有该遮挡训练；给冻结BARX临时涂黑像素不等于复现Cloak，也不能借其腕视角结果断言本外视角的根因 |
| [KITE v2，2026-10-20](https://arxiv.org/html/2606.22113v2)，§IV、附录A | 共享接触相关交互意图预测，与按具身运动学模型合成数据训练的动作解码器分离；接近、接触与操纵均在其意图范围内 | “共享交互意图＋具身动作解码”已存在。其点云和接触表征不等于本单RGB策略；其解码训练不构成我们已查明力学或阶段缺陷的证据。两台现有机器人使用相同Robotiq85，本数据也未独立测试新手型接触拓扑 |
| [Move-Then-Operate v4，2026-10-21](https://arxiv.org/html/2604.23620v4)，§4.1–4.4；[ICML正式页面](https://proceedings.mlr.press/v306/xu26aa.html) | 每个动作块用可学习阶段路由选择Move/Operate专家，监督阶段训练；利用MLLM、末端速度及子任务上下文自动标注阶段 | “接近之后进入操作”“阶段分类器选择专家”已存在。当前BARX没有可观测阶段路由，不能因不闭爪就断言其潜在阶段错了，更不能将另加闭爪阶段分类器直接作为创新 |
| [CrossZero，CVPRW 2026原文](https://openaccess.thecvf.com/content/CVPR2026W/GigaBrainChallenge/papers/Ge_CrossZero_Zero-Shot_of_Unseen_Embodiment_Manipulation_via_Object-Centric_Hierarchical_Diffusion_CVPRW_2026_paper.pdf)，§3.1–3.4 | 多视角RGB-D中移除机器人点云，物体功能位姿辅助编码，先生成末端动作，再解码关节动作；未见具身IK解码的蒸馏使用50条策略仿真rollout与IK监督 | “物体中心动作＋具身解码”已存在；不能把整套方法说成无任何目标rollout，也不能把其RGB-D输入能力归给本纯RGB日志。论文已下载原文可复核；本轮网页直接重取遇403，未据搜索摘要补写细节 |
| [Chaumette & Hutchinson，Visual Servo Control Part I，2006](https://www-cvr.ai.uiuc.edu/~seth/ResPages/pdfs/ChaHut06.pdf)，式1–5；普通状态机 | 视觉特征/位姿误差反馈控制、接近到位后的闭爪与抬升阶段切换均可按已有工程方法实现 | “接近＋闭爪触发＋抬升”本身没有原创性。视觉伺服需可用特征、几何及稳定执行条件；实现得到不等于本任务成功率已足够，更不等于8cm内盲闭爪就有效 |

Cloak是训练与部署相配套的方法；KITE需要交互预测和具身解码训练；Move-Then-Operate需要阶段路由与专家训练；CrossZero的观测和适配预算也与本数据不同。本轮全部未新训练或仿真，不能将上述方法列作“已经失败的Baseline”，也不能宣称完整标准适配已被排除。原文版本、章节及已下载文件校验见 [literature_sources.json](../evidence/interaction_initiation/literature_sources.json)。

## 什么已被本数据识别，什么没有

160条旧轨迹证明：Counter→Sink闭爪37/40与5/40的差别，在保存的原始策略输出中已经存在。93,798个命令的映射与队列完全一致；Panda有27条进入8cm接近代理后整段不闭爪，而逆向任务两台机器人都37/40闭爪。这是**任务方向依赖的策略输出失配**。

但尚缺三个必要识别环节：第一，接近代理不能认证同等抓取可行性；第二，加入姿态和运动历史约束后仅2/4对描述性比较有共同支持，且不是严格因果配对；第三，没有独立改变具身外观、同时保持任务线索和实际进度的可信图像干预。源首次闭爪锚定还带来选择偏差。故当前不能把“视觉外观引起进度误判”“阶段学习干扰”“接触意图解码失配”中的任何一个提升为已经验证的新机制。[完整审计与计数](INTERACTION_INITIATION_AUDIT.md)

## 为什么当前不提出唯一算法

| 候选包装 | 判断 |
| --- | --- |
| 物体近了就覆盖网络夹爪动作 | 普通触发/状态机；真实抓取条件未认证，且会改变后续观测和动作，无新增有效性证据 |
| 增加Move/Grasp阶段分类或双专家 | 与已有行为分阶段直接重合；本数据没有标注或识别独立新阶段变量 |
| 遮掉机器人区域让策略看物体 | 视觉具身不变性已有方法；当前也未证明此处的失配由该因素导致 |
| 共享接触意图再用目标解码器 | KITE已明确覆盖；本两臂同夹爪证据不支持新接触形态机制 |
| 物体中心轨迹、IK或视觉伺服 | 已有技术；未证明普通控制的充分实现或标准适配不能解决此任务 |

本轮没有发现一个额外的、已观测且可验证的决策变量，能在控制真实抓取条件和历史后解释该方向依赖，并构成上述方法没有直接覆盖的机制。因此给算法起名、画网络结构或把多个已有模块拼接为“交互启动网络”都超出现有证据。

本判断不是“所有相关算法问题已被解决”，也不是“普通控制已足够”或“标准适配已足够”。准确表述是：**当前未证明需要新算法，也未识别足以选择新算法结构的机制**。新方法是否存在，与这批数据是否支持现在开发，是不同问题。

**唯一建议：暂不启动新的交互启动算法项目，保留本次已定位的策略输出失配及上游原因不可识别的证据结论。** 本轮无算法提案、无追加实验、无网络开发。
