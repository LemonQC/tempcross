## 2. 实验设计和可复现性

运行前固定协议见 [VALIDATION_PROTOCOL.md](VALIDATION_PROTOCOL.md)，未改变原有预注册门槛。全部参数等级见 [PARAMETER_SOURCES.md](PARAMETER_SOURCES.md)。官方源 XML、许可和 commit 固定于 `vendor/`，SR5 下载内容与固定 commit 的字节一致性记录于 `evidence/source_verification.json`。

- 开发 seed `314159`，独立测试 seeds `271828,161803,141421`；每种子 9 场景，每类 3 个。测试共 27 个场景，三类各 9 个。不进行拒绝采样；不可达和无解菜单也保留。
- 非对称长方体（固定有向标记），桌面抓取、两障碍受限抓取、抓取并定向放置。两种对向平行夹爪抓持，四种运输路径，共八个操作。放置时补偿抓持的 π 偏置，使物体最终 yaw 一致；测试已核验。不是任意旋转都等价的圆柱假设。
- 两臂基座位置与公共两指工具固定，分别用不同关节轨迹实现相同 TCP 路径。为分离运动链因素，**没有把共同代理手冒充 PGIA 或 Panda Hand**。
- 每场景有障碍存在／移除配对。三类中的无障碍基础抓取没有额外盒子，因而这类配对相同，是负对照而非新增独立样本。每臂交叉两组假设光学外参，得到 2×2 本体／安装因素。总计 144 条场景×障碍×机器人记录，1,152 条候选轨迹记录，2,304 条光学因素候选行。
- 主相机因素在相同**期望** TCP 轨迹上评估，避免把 IK 失败伪装为不可见；实际 FK＋本体遮挡另存并做探索性诊断。主因果分解不包含冗余关节改变本体遮挡的全部效应，不能称其完备观测模型。
- 抓取前且距接触面高度 >.20 m 时要求至少 .60 的顶面采样点可见；接触处可见性单独记录。此阈值是假设，排除近距盲区的实验范围在运行前明确，不是全程视觉保证。释放后撤退不算 approach。
- IK 预算每路点至多两个确定性起点、每起点 100 个优化 nfev；找到首个合格解即继续。7-DOF 冗余与不同初值会影响分支。总实际 nfev Panda 861,393、SR5 55,045，**未做跨本体等耗时优劣声明**。各选择器共享同一预算内生成的完整候选表，无额外感知或候选。

实际正式运行耗时 183.21 秒，八个宿主机 CPU 进程；环境锁定于 `requirements-validation.lock`。依赖首次缺失、冒烟检查与一次工程中断均记录于 `evidence/EXECUTION_NOTES.md`，部分数据保留，未混入正式统计。原始数据无物理测量、控制器或触觉输入；未使用 ROS、旧专家实验、ManiSkill 或神经网络。

## 3. 测试场景结果与物理因素分解

下表只统计 27 个 held-out 场景的障碍存在条件，每臂 216 个候选；场景是统计单元。置信区间由固定 seed 4242 的 2,000 次场景 cluster bootstrap 得到，不能把 216 候选当独立样本。数据来自 `statistics.json`、`integrity.json`。

| 几何代理指标 | Panda | SR5 |
|---|---:|---:|
| 全路径所有路点 IK 找到 | 187/216 = 86.57% | 188/216 = 87.04% |
| IK 找到且关节插值跟踪合格 | 141/216 = 65.28% | 160/216 = 74.07% |
| 加入碰撞代理后 F | 82/216 = 37.96% [23.15,54.17]% | 23/216 = 10.65% [1.39,21.77]% |
| 安装 A：期望轨迹观测 V | 79.17% | 79.17% |
| 安装 B：期望轨迹观测 V | 81.94% | 81.94% |
| 安装 A：F∧V | 64/216 = 29.63% | 18/216 = 8.33% |
| 安装 B：F∧V | 67/216 = 31.02% | 18/216 = 8.33% |
| 安装 A：存在可行不可见候选且有 F∧V 替代的场景 | 11/27 = 40.74% | 3/27 = 11.11% |

**A，纯运动学：** 同一候选下有 24 个 Panda 找到、SR5 未找到，反向 25 个。平均 IK 找到率差 SR5−Panda 为 +0.46 个百分点，95% CI [−15.74,+14.81] 个百分点。显示解集合／求解器输出有变化，但没有证据表明总体纯 IK 能力有稳定差距。冗余、关节范围与链的偏置是已建模因素；局部数值失败不能排除其他分支的可达性。

**B，纯相机：** 同一 TCP 和同一 mount 下两本体的期望视图严格相同，这是设计的因果控制。安装 A→B 改变可见候选比例 79.17%→81.94%，此变化只能归于假设的安装位置、障碍、手指遮挡与视锥，不可归于机器人本体。两安装没有实测来源，不能外推真实 D435i 性能。

**C，共同作用：** 同 mount 下可行集合的差异进入 F∧V；固定安装 A 时，69 个 Panda 可行候选在 SR5 代理上失效，反向 10 个，逐候选原因见 `transfers.csv`。F 差 −27.31 个百分点，95% CI [−44.91,−10.65]；场景正／负差 3／12，其余平局，探索性双侧 sign-test p=.03516（未作多重比较校正）。这只对固定代理模型和此分布有效。差距伴随大量环境碰撞标签，不能分配为“真实 SR5 本体劣势”，更不能宣称此时必需学习。

本体×相机合取指标差分之差 `[(SR5_B−SR5_A)−(Panda_B−Panda_A)]` 为 −1.39 个百分点，95% CI [−5.09,+1.86]，包含零。虽然存在“可行但不可见、换操作可解决”的静态冲突，本轮**未证实稳定非平凡的交互，更没有证明历史依赖或学习不可替代的耦合**。合取非加性可以只是集合交集的代数性质。

实际 FK＋本体遮挡探索性核查：Panda 的 187 个、SR5 的 188 个整路径 IK 找到候选有实际视图。期望可见但实际低于阈值，Panda A/B 为 0/0，SR5 为 1/2；其中没有降低可行候选的 F∧V 数量。此结果仍来自相同代理几何，不是独立视觉测量或独立任务结果。

## 4. 七种强对照：解释范围

所有算法均使用同一八个候选、同一完整场景表。IK-only 按 IK 与路径长度选；IK+collision 按 F 与路径长度选；visibility-only 按 V 选；weighted 使用 `.5 F + .5 visible_fraction`；analytic AND 返回第一个合格候选；geometry planning 在合格菜单中取最短关节路径；same-information finite-menu MPC 以完整 scoped horizon 枚举相同菜单。

这里的 MPC 是**静态确定性有限菜单的完整时域最优选择**，与 geometry planning 的约束／目标相同，所以结果相同；没有新观测或过程扰动，不应伪装成真正的闭环 receding-horizon MPC，也没有实现 CEM。枚举对这个有限菜单强于随机采样；菜单外几何重规划、多 IK 分支、真实信念空间规划仍未评估。不能由这一受限设定声称标准规划不足。

| 选择器 | Panda 安装 A/B | SR5 安装 A/B |
|---|---:|---:|
| IK-only | 13/27，14/27 | 3/27，3/27 |
| IK + collision | 13/27，14/27 | 4/27，4/27 |
| Visibility-only | 11/27，11/27 | 3/27，3/27 |
| Weighted feasibility | 15/27，15/27 | 4/27，4/27 |
| Analytic AND | 15/27，15/27 | 4/27，4/27 |
| Geometry-aware finite-menu planning | 15/27，15/27 | 4/27，4/27 |
| Same-information finite-menu full-horizon MPC | 15/27，15/27 | 4/27，4/27 |

**表中数字是选中 F∧V 的场景数，绝非成功率。** AND／规划达到任一候选满足 F∧V 的覆盖上限，本来就由相同标签定义；没有解的 12 个 Panda 场景与 23 个 SR5 场景不是“学习可补足的规划失败”。从这些分数得不到独立任务质量排名。低分可能来自菜单无解、局部 IK 分支、轨迹插值或代理误判；神经网络不能在相同标签与相同菜单上超过精确枚举上限。

因此 Q3 的严格答案有两部分：静态有限几何标签问题可用解析约束与枚举处理；**真实操作是否已足够，证据不足**。没有独立执行结果就不能声称解析方法已经解决所有实际任务，也不能声称它们稳定不足。

## 5. 失败案例与有效性威胁

测试集每臂 216 候选；标签可重叠，不可求和当总失败数。全部记录均已发布，没有只报平均值。

| 失败标签 | Panda | SR5 |
|---|---:|---:|
| IK 搜索失败，真实可达性未知 | 29 | 28 |
| 关节插值偏离目标路径 | 46 | 28 |
| 机器人—环境球包络碰撞 | 29 | 152 |
| 手—环境代理碰撞 | 75 | 58 |
| 携带物体代理碰撞 | 36 | 24 |

非近邻自碰撞与手臂间碰撞检查已执行，但此批数据无相应标签；这不验证其检出灵敏度。球包络相对于代理中心线保守，相对于真实机器人并非已证明保守。近邻链段排除、掌指球代替 OBB、携物球和单侧顶面采样均可能改变排序。环境碰撞标签合并桌面与障碍，尚不能单凭这个标签定位物理接触部位。

具体可复查失败见 `integrity.json` 的 scene/blocked/candidate 索引；`trials.json` 保存全部 q、每次 IK 误差、期望 TCP 与携物标志，`factorial.csv` 和 `transfers.csv` 保存原因。`strata.csv` 提供每 seed／任务族分层结果，未因定向放置更难而移除样本。

三项尤其重要：

1. **不能由 6-DOF vs 7-DOF 自动推出泛化结论。** 本轮没有多解全局搜索、冗余优化，也没有在碰撞时重新求 IK；这是工程验证不完整，不能拿它削弱几何 baseline 制造学习优势。
2. **这是三维几何软件检查，不是操纵仿真。** 未建模夹紧、抓持力闭合、质量、摩擦、接触、手指闭合或真实放置误差；不是物理抓放成功。没有实际相机噪声、反光、畸变、深度无效像素、估计误差或校准误差传播。
3. **原始真实前提未通过。** SR5 现场对应、PGIA 与 Panda 手真实 CAD/TCP、手眼、场景尺寸仍未核实；无完整官方网格、自碰撞允许矩阵、连续证书、停车位过渡或独立闭环结局。故不能按 A/B/C 为真实任务作最终分类，D 才符合原门槛。软件运行没有被阻断，所以不用 IMPLEMENTATION_BLOCKED 代替已经得到的软件结果。

## 6. Q1–Q5 与 T-RO 决策

**Q1：当前真正的跨具身差异在哪些物理因素？** 已建模的是官方六／七关节链、轴向和 link offsets、关节范围与冗余带来的解／轨迹变化，以及由此进入碰撞代理的外形位置变化。相机 mount 是独立因子；同 TCP／同 mount 下视图不应因自由度标签改变。真实 PGIA、D435i 和现场几何差异尚未确认，不能将代理结果包装成实测。

**Q2：是否发现非平凡耦合？** 发现静态候选中可行／可见冲突和替代；没有发现足以支持稳定复杂耦合的证据，差分交互 CI 含零；更无独立闭环失败机制。几何现象存在、需要联合约束、需要学习是三层命题，本轮只支持代理层的前两层。

**Q3：标准几何和规划是否足够？** 对固定有限菜单的几何约束问题，解析筛选／精确枚举达到覆盖上限，未发现剩余选择困难。对真实任务不能判定；未覆盖菜单外重规划和真实观测反馈，也没有独立结局。现有低代理覆盖不构成规划方法不足证据。

**Q4：COFT 不可替代贡献是什么？** 当前无法确定。共享意图、条件 IK、末端 mask、IK＋FoV 和约束视觉 MPC 都有直接先行工作；见 [NOVELTY_AUDIT.md](NOVELTY_AUDIT.md)。校准审计／受控 benchmark 可作为基础工作，但不是已经成立的新学习算法贡献。

**Q5：继续、调整还是停止？** 继续机制验证与参数校准；把假设收窄为“在明确误差与任务分布下，几何规划之后是否存在独立任务残差”。暂缓 T-RO 学习算法立项，并停止依据 v0 合取分数训练网络的分支。只有模型与独立执行终点通过、常规规划与状态估计仍有可复现残差时，才能重新审议情况 C。当前既不能宣布课题不可做，也不能声称具备 T-RO 水准。后续证据门槛见 [NEXT_STAGE.md](NEXT_STAGE.md)。

## 7. 复现与交付索引

```bash
python -m venv .venv
.venv/bin/pip install -r requirements-validation.lock
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 scripts/run_validation.sh
.venv/bin/python scripts/audit_results.py evidence/v1
```

- 代码：`coftvalidation/`，原始 v0：`coftprobe/`。
- 公开模型：`vendor/`、`configs/validation/`、`scripts/build_models.py`。
- 测试：`tests/`；实际执行 10 项通过，输出 `evidence/all_tests.txt`。这些是软件正确性检查，不是科学门槛通过。

- v0 和中断／开发记录：`evidence/v0*`、`dev_smoke*`、`implementation_interrupted*`。只有 `evidence/v1` 为正式结果。
- manifest 固定输入／实现 SHA256，完整性脚本校验所有场景和候选无丢失、所有模型／协议 hash 匹配；独立执行结果数量明确为 0。

报告允许科研负责人作出“暂缓算法立项、先补齐证据”的具体决定；不以多写代码或测试通过替代科学结论。

存储说明：三个较大的逐轨迹 JSON 在 Git 中以 `trials.json.gz` 无损保存；运行实验会生成普通 `trials.json`，`gzip -dk evidence/v1/trials.json.gz` 可恢复提交的原始 JSON。完整性脚本同时支持两种形式，gzip 没有改变任何数值或丢弃任何失败记录。`evidence/replay_check.txt` 记录了独立重算两臂一个测试候选，完整记录精确一致。
