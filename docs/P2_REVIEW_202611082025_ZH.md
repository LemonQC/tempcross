# 最新专家意见：P2 执行前分析与有限轮次决策

当前建议：值得执行这轮机制验证和标准适配；现阶段不启动 COFT 新网络。研发决策限定为最多两批冻结评测。简单控制或标准适配足够时停止新算法分支；资源或证据不足时同样暂不立项，保留具体限制，不进入无限调参。

## 2. 已经查清的实施问题

### 2.1 未闭爪远离原阈值，不能假设是小偏差

本轮对 17 条全程未发送闭爪命令的 Joint Reps/Panda 轨迹，按实际执行步展开原始动作块。夹爪原始输出的全局最小值为 **0.738448**，各 episode 中位数在 **0.935397–0.947195**。

官方动作处理为 `-sign(2*g-1)`，所以 `g<0.5` 才对应环境闭爪正指令。离线阈值筛查如下：

| 假定闭爪条件 | 17 条中至少触发一次的条数 | 被标记为闭爪的旧轨迹动作步 |
|---|---:|---:|
| g < 0.50 / 0.55 / 0.60 / 0.70 | 0 | 0 |
| g < 0.80 | 2 | 48 |
| g < 0.85 | 5 | 58 |
| g < 0.90 | 17 | 439 |
| g < 0.93 | 17 | 3316 |

这是旧状态序列上的信号检查，未使用滞回，也不是成功率预测。干预一旦改变物理状态，后续图像及策略输出会变化。它只说明：小幅调整阈值不足以在这些旧状态上触发闭爪；大幅偏置可能提前误闭或影响释放，必须用有限开发实验验证。

实际指关节状态有六个分量，不能把其中一个关节值直接当成夹爪宽度或稳定抓持。需要由指垫几何计算真实开口，并分开记录命令、实际运动与物体接触。

### 2.2 原数据足够重建指垫运动，但不足以直接证明可抓

HDF5 已保存全部 body 的位置、四元数、关节状态、目标位姿及接触几何名；官方 frozen XML 保存指垫相对所属 finger body 的局部几何。因此可以重建指垫、夹爪中心和 TCP 相对物体的 SE(3)，无需重跑旧 80 次。

当前 Robotiq85 指垫是 box，局部半尺寸为 `[0.010, 0.001, 0.01675] m`，局部位置为 `[0, -0.0245203, 0.03242] m`。这些来自实际冻结模型。应使用相应模型的 body 变换和物体碰撞几何，检查夹持开口、插入深度、方向和扫掠空间，不能继续用 EEF 到物体中心 10cm 代替。

几何区域相交只定义“候选抓取机会”，不能保证摩擦、接触与后续抬升成功。对候选时刻，最小因果验证是同一物理状态下比较原夹爪命令与辅助闭爪。若无法确认，应记录 UNKNOWN，不能把 17 条全部判成“已合法对齐但拒绝闭爪”。

原 telemetry 没有完整保存控制器内部状态和所有求解器状态。构造反事实时，不能仅 set qpos/qvel 就声称精确恢复。优先从官方初态重放所需的已记录动作前缀，核对分支点状态，再进行短时夹爪干预；只选开发集中必要案例，不重新执行整个旧评测。

segmentation 可通过同一模型和记录状态进行无积分的离线渲染。记录可见像素，并在需要判断遮挡比例时提供同状态无外部遮挡参考；单个像素数不能区分距离、形状和遮挡。上述真值仅用于诊断和明确声明的 B2。

### 2.3 索引 20–39 不是 start_seed=1020

官方 evaluator 总是读取 bundle 的前 N 条，`start_seed` 不是条件偏移参数。visible-target 协议还检查 bundle 起始 seed。当前运行器同样没有 condition offset。

索引 20–39 的实际 seed 为：

`1031,1032,1034,1037,1038,1039,1040,1041,1043,1045,1046,1049,1051,1052,1053,1054,1055,1056,1058,1063`。

推荐独立 P2 入口先调用官方 loader 完整验证原 bundle，再对已经验证的 entries/states/XML 统一取 `[20:40]`，交给评估过程。保留原 condition_id、原 episode index、metadata/state/model hashes，另外记录本批 trial index，不修改官方仓库。

不要直接把 JSON 的后 20 条拷出：官方 loader 要求 episode 索引从零连续，简单切片会失败。也不要为了满足 loader 静默改写条件 ID。需要针对取窗和一一对应关系做小型合同测试。

### 2.4 target_50/pnp 是每个方向 50 条，总共 100 条

官方 manifest 的 `target_50 --target panda --task pnp` 选取两个 HDF5：Counter→Sink 50 条，564,120,784 bytes；Sink→Counter 50 条，716,265,939 bytes。合计约 1.19 GiB。公开 RLDS 元信息也明确为 100 episodes。

本轮在线解析并固定的 Panda RLDS revision 为 `6e297509924c831c722180212d13f21686676e8e`，列出文件约 0.904 GiB。原始 HDF5 revision 为官方固定的 `c8b3aba2dfbbfbafa67fa82466320945d560208f`。

为检验“标准 BARX 适配”，推荐保持官方两个方向联合训练，并明确写“每任务 50 条、PnP 共 100 条”；正式评估仍只运行 Counter→Sink。若严格限定总共 50 条 Counter→Sink，应另外标成受限适配，不得将它失败视为官方标准适配无效。两种方法必须使用完全相同的目标数据，不能只给其中一个增加示范。

[Panda 数据卡，固定 revision](https://huggingface.co/datasets/ajaysri/robocasa-x-target-panda-pnp/blob/6e297509924c831c722180212d13f21686676e8e/README.md)

### 2.5 官方适配混入源数据，不能漏下载或静默去掉

`panda_xp_900_pnp` 解析为 `mg_pnp_lite:0.05 + panda_pnp:1.0`，沿用源统计和源 VQ。数据加载器还按各集合的 transitions 数量重加权，因此 0.05:1.0 不能直接解释成最终抽样概率。

源 RLDS 固定 revision 为 `a2b5256a48428ea56064b0afb3dc184a045b10ae`，公开文件约 23.189 GiB、1800 条示范；两方向各 900 条。当前源 checkpoint 的统计记录为 805,006 transitions。只需要这两个 RLDS 子集，加目标原始文件做来源审查，无需完整 284 GiB 原始库。

来源审查还应核对示范实际机器人/夹爪、相机、动作符号、物体实例、场景与初态。现有公开元信息不能证明与冻结测试条件没有精确重叠；需要检查原始示范元数据和初态。相同物体类别或厨房布局本身不等于数据泄漏。

### 2.6 单卡 full tuning 与 LoRA 的结论强度不同

官方 VLA loop 明确断言 `grad_accumulation_steps == 1`；启动器同样拒绝用梯度累积模拟大 global batch。现有 `--gpus 1 --global-batch-size 1 --per-device-batch-size 1` dry-run 成功生成命令，但没有执行训练，不能据此判断显存足够。

本轮 CPU mmap 检查 checkpoint，有约 13.886 亿个状态元素，包含视觉、语言和 projector。按全部元素参与 FP32 权重、梯度及 Adam 双状态的粗略 16 bytes/元素估算，静态内存约 20.69 GiB，尚未包括激活与临时缓冲；这不是实际显存测量，也不能直接据此报告 OOM。

单卡探针应实际完成最长训练样本的前向、反向、optimizer step、保存、重新加载和合法推理，并记录 peak allocated/reserved。优先使用已有 pins 与官方 full tuning。仅在真实 OOM 后，允许一次明确标注的 LoRA 后备方案；若后备也失败，停止适配分支并记录 D。

源码已有 `ddp-lora`，无需另造适配网络，但它输出 PEFT adapter 目录，而官方 full checkpoint 为 `.pt`。必须验证正确底座上的 adapter 重载/合并及 evaluator 兼容性，不能只验证训练 loss。

官方示例为 3000 steps、global batch 256，共 768,000 个 batch 样本位置。单卡 batch 1 同样跑 3000 steps 仅有前者 1/256 的样本位置；Joint Reps 的辅助训练任务还改变监督构成。两种方法同样少训，并不代表标准适配已得到充分验证。应同时记录 optimizer steps、训练样本/目标数据暴露量、action 与辅助监督量，以及实际计算预算。

小 batch 或 LoRA 获得强闭环恢复，可以支持“常规适配已有足够作用”；小 batch、LoRA 或明显不足预算下的失败，不能排除充分标准适配，不能用来宣布 C。

另一个代码细节：当前 Prismatic 推理函数只将图像和语言传给 `predict_action`，没有使用 evaluator 构造的 `obs['state']`。以后若候选残差引入额外机器人状态，必须控制信息差异；本轮 B1 保持仅使用原始夹爪信号及其历史。

## 3. 一次开发冻结，最多两批正式裁决

以下为建议的执行约束，尚未执行；最终机器可读协议必须在第一次测试前冻结。

**准备批只使用旧 0–19 开发条件。** 完成旧轨迹精细诊断，选择 B1，校验 B2，以及进行训练可行性探针。B1 最多比较三个固定阈值候选，例如 0.85/0.90/0.93，统一滞回宽度 0.03 和最短保持 8 个动作步；这些是待开发验证的建议值，不是专家指定值，也不是已确定的有效控制器。候选只在预先列出的 8 个开发条件上运行，最多 24 次开发干预，选择一次后冻结，不追加第四种测试驱动规则。

B1 每个时刻只改变第七维夹爪控制，手臂六维沿用当次官方策略预测。其后观察和策略响应允许因闭环干预而改变，但不得声称两条完整轨迹的手臂动作仍完全相同。需要记录关闭触发、实际开口及保持/释放时序，防止用全程夹紧换取虚假的抓取改善。

B2 只在几何机会经开发集验证后触发辅助闭爪；具体保持与释放规则也必须提前声明。若额外利用容器真值控制释放，须单独披露此干预因子，不能把其收益全部归为“闭合时机”。不得通过瞬移、固定物体或改质量/摩擦来制造可抓性。Case 001 的后退只作独立开发案例，不混入 B1 或暗中推广为正式方法。

**第一批正式评测使用 20–39，控制参数、两份适配配置、训练预算和最终 checkpoint 选择规则均在看到本批结果前冻结。** 专家要求的五组 100 次，加两份目标适配各 20 次，共 **140 次**。这使标准适配与干预可在相同的、独立于训练和开发的条件上逐次比较。

| 方法 | 机器人 | 次数 |
|---|---|---:|
| Original Joint Reps | UR5e | 20 |
| Original Joint Reps | Panda | 20 |
| Original No Reps | Panda | 20 |
| B1 简单夹爪修正 | Panda | 20 |
| B2 特权抓取诊断 | Panda | 20 |
| No Reps 标准/明确标注的受限适配 | Panda | 20 |
| Joint Reps 标准/明确标注的受限适配 | Panda | 20 |

训练若技术受阻，仍可完成五组 100 次；缺失适配结果必须是 null/blocked，不能填成 0%。已冻结的适配可以在同一测试批顺序执行；一旦根据测试结果修改适配超参、checkpoint 或控制规则，这批就不能继续被称为未用于选型的测试集。

**第二批只用于确认 C 候选或预先定义的边界结果，使用保留的 40–59。** 所有可比较的方法使用相同条件，最多再 140 次，模型与规则保持原冻结版本。不在第二批前调优，不因某条失败更换条件，不安排第三轮继续搜索。

全流程预算建议为最多 24 次 B1 开发干预、第一批 140 次、必要时第二批 140 次，另加提前列明的少量 B2/分支验证和训练可行性探针。实际新增开发次数也必须入账，不把它们隐藏在“只跑一次”中。

## 4. 预先给出停止和继续规则

专家给出了 A/B/C/D，但没有数值门槛。下面是建议的研发筛查门槛，须在正式测试前冻结；它们不等于论文显著性或统计功效保证。

令同一 Panda 条件上，r 为原来失败、干预后成功的数量，b 为原来成功、干预后失败的数量；必须同时报告 r、b、净变化及阶段变化。不能只报总体百分比。

| 结果 | 建议操作判据 | 研发决定 |
|---|---|---|
| A：简单控制足够 | B1 救回至少一半 B0 失败，破坏不超过 1 条原成功，且核心抓取失败相应减少 | 停止以该抓取问题为理由的新学习算法分支 |
| B：标准适配足够 | 至少一份常规适配相对其未适配 Panda 基线净增至少 4/20，成功数距同批源参考不超过 2 条、回退不超过 1 条，主要阶段失败同步缓解 | 停止“零样本差距证明新算法必要”的立项逻辑；保留复现和适配结论 |
| C 候选：残余失效 | B1 和两份充分、可信的标准适配在同批至少 5 条条件上共同失败，B2 在其中至少救回 3 条；普通源基线有可信成功参考，且机制可定位 | 只允许进入第二批确认，不立刻设计网络 |
| C 确认 | 独立第二批以相同冻结方法再次出现上述结构，适配充分性、信息边界、条件重叠和真实物理证据均满足 | 值得进一步做算法与新颖性审查；仍不自动达到 T-RO 标准 |
| D：不足或边界未过 | 训练不可行、仅受限适配失败、Oracle 未验证有效、源也缺乏可信能力、机制不清或第二批未确认 | 当前分支暂不立项；不通过继续调阈值/换种子制造 C |

这些规则有意允许 D 成为终止研发投入的决定。它表示本资源和证据下尚不值得启动新网络，并不否定整个 Cross-Embodiment 方向。即使未跨过 A/B 的建议数量门槛，也不能反过来推导出 C。

普通 B1 若已恢复到源参考附近，却仍保留一些源上也常见的失败，不应再把这些共同任务困难包装成跨具身特有缺口。LoRA 单次训练失败、损失下降不足或显存不足都不能帮助满足 C。

## 5. Oracle 和算法位置的最终解释边界

B2 是指定夹爪干预、指定开发规则下的特权诊断参考，不是数学意义的理论上界。它失败可能来自未到达候选姿态、错误 Oracle、保持/释放设计、手臂动作或观测策略；不能据此证明目标机器人不可完成任务。它成功证明对应实际干预可恢复任务，也不证明仅凭普通视觉信息就能实现相同判断。

若普通方法被充分排除，算法位置也只能随残余机制确定：候选抓取区域内的动作/时机错误，才考虑夹爪或动作阶段；运动跟踪差异需先比较标准运动学/工具坐标修正；确有可见性失效证据才讨论感知问题。目前没有证据优先选择具身残差，更没有 Eye-in-Hand 联合可观测性算法的立项依据。
