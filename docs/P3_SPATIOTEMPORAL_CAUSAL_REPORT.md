## 具体机制与不能过度归因的地方

四个困难案例22/24/26/29，A1 闭合时相对源模板的位置差约27/38/51/66mm，方向差约8/16/29/25°。A3 的标准接近和 pose-gated 闭爪均建立真实接触抬升，说明 Panda 抓持在原物理参数下可恢复；不能将旧失败解释为硬件根本不能抓取。

但 A1 固定原机械臂动作，四例在强制闭合期间实际 TCP 只向上约12/6/12/0mm。A3 额外执行预定抬升和运输，因此 **A1 不抬升、A3 抬升不能单独证明静态位姿是唯一原因**。它还包含接触后动作/反馈阶段的差别；A1 是开环动作重放，不能等同于会随图像变化重新出动作的 B1 闭环策略。

条件34更有辨别力：A1 TCP 上移约93mm，闭合时却距源模板约64mm，未形成稳定抓持；A3 则抓持并完成任务。结合 A2/A3 相同位姿路径、不同夹爪时序，证据支持“空间接触、闭合时机和后续动作必须共同对齐”，而非只调一个夹爪阈值。普通旧 LoRA 已能救回34，故它不是新算法独占贡献。

A3 三次完整任务失败为22、29、39，均已抓持，失败发生在后续运输/放置/退离。放置阶段最小位置误差约200/69/271mm，整段轨迹还存在厨房接触；成功案例也有接触，故仅接触计数不能证明唯一原因。没有数学IK不可达证明，不将OSC未收敛写成“机器人不可达”或“网络表达不足”。条件29源轨迹没有显式开爪命令，冻结规则使用末次接触后一状态作为释放代理，这也限制了释放几何的解释。

闭爪门控相对于分支时锚定的目标计算，八例五状态容差均核验。独立列出的“当前物体相对误差”会因物体在接近时移动而不同；例如22当前物体相对角差约10.7°，不代表违反锚定目标的10°门控。
